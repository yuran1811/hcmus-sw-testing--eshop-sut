# API Test Runner — Newman Execution & Bug Reporting

## Purpose

Execute API test collections via Newman CLI, produce HTML reports, identify failing tests as bug
candidates, and set up CI/CD integration. This skill implements HW06 pipeline Steps 4 (Execute)
and 5 (Report Bugs), plus the CI/CD integration requirement.

## When to use

| Trigger | Action |
| --- | --- |
| User has a Postman collection and wants to run it | EXECUTE flow |
| User wants to see test results and identify bugs | REPORT flow |
| User asks for CI/CD / GitHub Actions setup | CI/CD flow |
| User wants to re-run after fixing tests | RE-EXECUTE flow |

## Prerequisites

Before running, verify:

1. **Newman installed**: `npm install -g newman newman-reporter-htmlextra`
2. **Backend running**: The SUT must be accessible at the configured baseUrl.
3. **Collection file exists**: Valid Postman Collection v2.1 JSON.
4. **Environment file exists**: Contains baseUrl, studentId, credentials.
5. **Student ID configured**: Must appear in environment or collection variables.

## Execution workflow

### Phase 1: Pre-flight checks

```bash
# Verify newman is installed
newman --version

# Verify backend is reachable
curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/api/products

# Verify collection file is valid JSON
node -e "JSON.parse(require('fs').readFileSync('path/to/collection.json'))"
```

If newman is not installed, install it:

```bash
npm install -g newman newman-reporter-htmlextra
```

### Phase 2: Token acquisition (if auth required)

Before running auth-dependent tests, acquire fresh tokens. Create or use a setup request
in the collection's pre-request script:

```javascript
// Collection-level pre-request script (already in collection if generated by test-writer)
// Acquires admin and user tokens on first request
if (!pm.collectionVariables.get('adminToken')) {
    pm.sendRequest({
        url: pm.collectionVariables.get('baseUrl') + '/api/login',
        method: 'POST',
        header: { 'Content-Type': 'application/json' },
        body: {
            mode: 'raw',
            raw: JSON.stringify({
                email: pm.environment.get('adminEmail'),
                password: pm.environment.get('adminPassword')
            })
        }
    }, function (err, res) {
        if (!err && res.code === 200) {
            pm.collectionVariables.set('adminToken', res.json().token);
        }
    });
}
```

### Phase 3: Execute collection

#### Full collection run

```bash
newman run {COLLECTION_PATH} \
  -e {ENVIRONMENT_PATH} \
  --timeout-request 10000 \
  --reporters cli,htmlextra \
  --reporter-htmlextra-export {REPORT_PATH} \
  --reporter-htmlextra-title "{API_NAME} API Test Report" \
  --reporter-htmlextra-browserTitle "{API_NAME} Tests" \
  --bail failure \
  2>&1 | tee {LOG_PATH}
```

#### Data-driven run (specific folder)

```bash
newman run {COLLECTION_PATH} \
  -e {ENVIRONMENT_PATH} \
  --folder "06 - Data-Driven" \
  -d {DATA_FILE_PATH} \
  --reporters cli,htmlextra \
  --reporter-htmlextra-export {DATA_REPORT_PATH} \
  2>&1 | tee {DATA_LOG_PATH}
```

#### E2E workflow run (sequential, no bail)

```bash
newman run {COLLECTION_PATH} \
  -e {ENVIRONMENT_PATH} \
  --folder "07 - E2E Workflow" \
  --reporters cli,htmlextra \
  --reporter-htmlextra-export {E2E_REPORT_PATH} \
  2>&1 | tee {E2E_LOG_PATH}
```

### Phase 4: Parse results and identify bugs

After newman completes, parse the CLI output or the JSON reporter output to extract:

1. **Total tests**: count of all `pm.test()` assertions.
2. **Passed**: tests that passed.
3. **Failed**: tests that failed — each is a **bug candidate**.
4. **Skipped**: tests that were skipped.
5. **Response time stats**: min, max, average, p95.

For each failed test, extract:

| Field | Source |
| --- | --- |
| Test name | The `pm.test("...")` description |
| Request | Method + URL |
| Expected | What the test asserted |
| Actual | What the API returned (status code, body snippet) |
| Category | From the test name prefix (Functional/Contract/Security/Integration) |

### Phase 5: Generate bug report

For each genuine bug (failed test that reveals an actual SUT defect, not a test error):

```markdown
# BUG-{API}-{NNN}: {Short description}

## Severity

{Critical / Major / Minor / Trivial}

## Related test case

TC-{API}-{NNN}

## Steps to reproduce

1. {Step from the test case}
2. {Step}
3. {Step}

## Expected result

{What the spec says should happen}

## Actual result

{What actually happened — status code, response body}

## Evidence

- Newman report: {link to HTML report}
- Screenshot: {if applicable}

## Environment

- Base URL: {baseUrl}
- Student ID: {studentId}
- Date: {timestamp}
```

## CI/CD flow — GitHub Actions

When the user asks for CI/CD integration, generate a GitHub Actions workflow:

```yaml
# .github/workflows/api-tests.yml
name: API Tests

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  api-tests:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'

      - name: Install backend dependencies
        working-directory: ./backend
        run: npm ci

      - name: Start backend server
        working-directory: ./backend
        run: |
          node server.js &
          sleep 5
          curl -f http://localhost:3000/api/products || exit 1

      - name: Install Newman
        run: npm install -g newman newman-reporter-htmlextra

      - name: Run API tests
        run: |
          newman run tests/postman/collections/{API_NAME}_tests.postman_collection.json \
            -e tests/postman/environments/eshop_local.postman_environment.json \
            --reporters cli,htmlextra \
            --reporter-htmlextra-export tests/postman/newman-reports/{API_NAME}_report.html

      - name: Upload test report
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: newman-report
          path: tests/postman/newman-reports/
```

### Two-commit strategy (HW06 requirement)

The HW06 requires two sample commits:

1. **All-passing commit**: Run the full collection, all tests pass. Commit with message:
   `"test: all API tests passing for {API_NAME}"`

2. **One-failing commit**: Intentionally break one test (or expose a known SUT bug).
   Commit with message: `"test: demonstrate failing test for {BUG_DESCRIPTION}"`
   Then revert or fix in a follow-up commit.

## Troubleshooting

| Problem | Likely cause | Fix |
| --- | --- | --- |
| `connect ECONNREFUSED` | Backend not running | Start `node server.js` in backend/ |
| `getaddrinfo ENOTFOUND` | Wrong baseUrl | Check environment file baseUrl value |
| `Unexpected token` in collection | Invalid JSON | Validate collection JSON with `node -e "..."` |
| All auth tests fail with 500 | Token format wrong | Check JWT structure, verify login endpoint works |
| Data-driven tests all fail | Data file schema mismatch | Ensure data file fields match request body |
| `newman: command not found` | Newman not installed | `npm install -g newman newman-reporter-htmlextra` |
